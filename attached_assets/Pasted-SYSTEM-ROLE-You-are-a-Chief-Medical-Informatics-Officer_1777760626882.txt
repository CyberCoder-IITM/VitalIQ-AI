FEATURE 1 — PREDICTIVE DETERIORATION FORECASTER
═══════════════════════════════════════════════════════════

This is the single most valuable clinical AI feature.
"We predict deterioration 6 minutes before it happens."
This is what Philips EarlyVue and Epic Deterioration 
Index charge hospitals $2M/year for.

Create backend/ai/deterioration_forecaster.py:

  Class DeteriorationForecaster:
    
    Per patient, maintains:
      vitals_history: last 20 readings (60 seconds)
      news2_history: last 20 NEWS2 scores
      forecast_cache: last computed forecast
    
    Method: forecast_patient(
      patient_id: str,
      vitals_history: list[VitalSigns],
      news2_history: list[int]
    ) -> DeteriorationForecast
    
    Algorithm — implement from scratch:
    
      STEP 1 — Trend Extraction per vital:
        For each of 6 vitals (HR, SBP, RR, SpO2, Temp, GCS):
          Fit linear regression on last 10 readings
          slope = (y[-1] - y[0]) / len(y)
          Extract: current_value, slope, acceleration
                   (second derivative of slope)
      
      STEP 2 — NEWS2 Trajectory:
        news2_slope = linear regression on news2_history
        news2_acceleration = second derivative
        predicted_news2_5min = current + (slope × 10)
                               + (0.5 × acceleration × 100)
        Clamp: 0 to 20
      
      STEP 3 — Specific Deterioration Pattern Detection:
        
        SEPSIS_PATTERN: 
          HR > 100 AND RR > 22 AND Temp > 38.3 OR < 36
          AND trending worse on all three
          → sepsis_probability: float
        
        RESPIRATORY_FAILURE_PATTERN:
          SpO2 < 94 AND RR > 25 AND trending worse
          → resp_failure_probability: float
        
        HEMODYNAMIC_SHOCK_PATTERN:
          SBP < 100 AND HR > 100 (shock index > 1.0)
          AND SBP_slope < -2 (falling BP)
          → shock_probability: float
        
        NEURO_DETERIORATION_PATTERN:
          GCS falling (slope < -0.3)
          AND either HR or BP abnormal
          → neuro_deterioration_probability: float
        
        CARDIAC_ARREST_RISK:
          HR < 40 OR HR > 150
          AND SBP < 80
          AND news2_slope > 0.5 (rapidly rising)
          → cardiac_arrest_probability: float
      
      STEP 4 — Time to Threshold Estimate:
        If news2_slope > 0:
          time_to_news2_7 = (7 - current_news2) / news2_slope
          (in readings × 3 seconds = actual seconds)
          Convert to minutes
        
        If news2_slope <= 0 or current_news2 >= 7:
          time_to_news2_7 = None (already critical or improving)
      
      STEP 5 — Intervention Windows:
        "Golden Hour" detection:
          If any pattern probability > 0.6 AND 
             current NEWS2 < 7 (still actionable):
          intervention_window: str
            "ACT NOW" if time_to_7 < 5 min
            "ACT WITHIN 10 MIN" if < 10 min
            "MONITOR CLOSELY" if < 20 min
            "STABLE" otherwise
      
      Return DeteriorationForecast(
        patient_id: str,
        timestamp: ISO8601,
        current_news2: int,
        predicted_news2_5min: int,
        predicted_news2_10min: int,
        news2_trajectory: "RAPIDLY_RISING"|"RISING"|
                          "STABLE"|"FALLING"|"RAPIDLY_FALLING",
        vital_forecasts: {
          vital_name: {
            current: float,
            predicted_5min: float,
            slope: float,
            direction: "WORSENING"|"STABLE"|"IMPROVING"
          }
        },
        patterns: {
          sepsis: float,
          respiratory_failure: float,
          hemodynamic_shock: float,
          neuro_deterioration: float,
          cardiac_arrest_risk: float
        },
        dominant_pattern: str | null,
        dominant_pattern_probability: float,
        intervention_window: str,
        time_to_critical_minutes: float | null,
        confidence: float,
        forecast_basis: str   (explanation sentence)
      )
    
    Background task: run forecast every 15 seconds 
    for all patients. Store results in dict by patient_id.
    
    Routes:
      GET /api/forecast/{patient_id} → DeteriorationForecast
      GET /api/forecast/all → all 8 forecasts
      GET /api/forecast/critical → 
        patients where intervention_window != "STABLE"

FEATURE 2 — CLINICAL HANDOFF GENERATOR
═══════════════════════════════════════════════════════════════

Shift handoffs are one of the highest-risk moments in 
clinical care. 80% of medical errors happen during handoff.
VitalIQ auto-generates SBAR handoff reports.

Create backend/ai/handoff_generator.py:

  SBAR = Situation, Background, Assessment, Recommendation
  The gold standard handoff format used globally.
  
  Function: async generate_sbar(
    patient: Patient,
    vitals: VitalSigns,
    news2: NEWS2Result,
    forecast: DeteriorationForecast,
    labs: list[LabResult],
    interactions: list[DrugInteraction],
    differential: DifferentialDiagnosis,
    icu_prediction: ICUPrediction,
    alerts: list[ClinicalAlert]
  ) -> SBARHandoff
  
  SBARHandoff(
    patient_id: str,
    generated_at: ISO8601,
    outgoing_provider: str,
    
    situation: str,
      "Dr. [name], I'm calling about [patient name], 
       [age/sex] in [bed], admitted for [chief complaint].
       [One sentence current clinical status]."
    
    background: str,
      "Patient has a history of [conditions]. 
       Current medications include [key meds].
       Relevant allergies: [allergies].
       They arrived [X hours] ago with [complaint].
       Key findings: [top 3 objective findings]."
    
    assessment: str,
      "I believe the problem is [top diagnosis].
       NEWS2 score is [n] ([risk level]).
       ICU admission probability is [n]%.
       [Deterioration forecast if relevant].
       [Drug interactions if relevant]."
    
    recommendation: str,
      "I am recommending [specific actions].
       I need you to [specific requests].
       Do you have any questions?"
    
    urgency: "ROUTINE"|"URGENT"|"EMERGENT",
    key_concerns: list[str],    (top 3 bullet points)
    pending_items: list[str],   (outstanding orders/results)
    verbal_summary: str         (30-second spoken version)
  )
  
  Gemini prompt:
    "You are generating an SBAR clinical handoff report.
     Write in first-person physician voice.
     Be specific — use actual values from the data.
     Use real clinical terminology.
     The SITUATION must be 2-3 sentences maximum.
     The BACKGROUND must include only clinically relevant history.
     The ASSESSMENT must state a clear clinical impression.
     The RECOMMENDATION must be specific and actionable.
     
     CRITICAL: verbal_summary must be speakable in 30 seconds.
     It should be natural spoken English, not medical jargon.
     Format: plain JSON. {situation, background, assessment, 
     recommendation, urgency, key_concerns, pending_items, 
     verbal_summary}"
  
  Route: POST /api/ai/handoff/{patient_id}
  Route: GET /api/ai/handoff/department → 
    generates handoff for ALL 8 patients as a shift report

FEATURE 4 — SEPSIS BUNDLE TRACKER
═══════════════════════════════════════════════════════════════

The Sepsis-3 bundle is a standardized set of interventions
required within 1 and 3 hours of sepsis recognition.
Hospitals are penalized by CMS if bundles are incomplete.
This is a real compliance requirement worth millions.

Create backend/analysis/sepsis_tracker.py:

  Class SepsisTracker:
    
    Per patient, evaluate Sepsis-3 criteria:
    
    SEPSIS SCREENING (qSOFA):
      qSOFA score (Quick Sequential Organ Failure Assessment):
        RR ≥ 22: +1
        Altered mentation (GCS < 15): +1
        SBP ≤ 100: +1
      qSOFA ≥ 2: sepsis concern
    
    SEPSIS BUNDLE — 1 HOUR BUNDLE:
      □ Measure lactate level
      □ Obtain blood cultures before antibiotics
      □ Administer broad-spectrum antibiotics
      □ Begin 30mL/kg crystalloid for hypotension/lactate≥4
      □ Apply vasopressors if MAP < 65 despite fluids
    
    SEPSIS BUNDLE — 3 HOUR BUNDLE:
      □ Reassess volume status
      □ Reassess tissue perfusion
      □ Document reassessment
    
    SepsisStatus(
      patient_id: str,
      qsofa_score: int,
      qsofa_criteria_met: list[str],
      sepsis_concern: bool,
      sepsis_confirmed: bool,     
      bundle_1hr: {
        item: str,
        completed: bool,
        time_to_complete: int | null,   (minutes)
        overdue: bool
      }[],
      bundle_3hr: same structure,
      time_since_recognition: int,     (minutes, if recognized)
      bundle_compliance: float,         (0-1, % completed)
      cms_penalty_risk: bool,
      alert_generated: bool
    )
    
    Sepsis "recognition" triggered when:
      qSOFA ≥ 2 AND (Temp > 38.3 OR < 36 OR WBC > 12 or < 4)
      Start the clock at that moment
    
    Route: GET /api/sepsis/{patient_id}
    Route: GET /api/sepsis/all → all patients screening results
    Route: POST /api/sepsis/{patient_id}/bundle/{item_id}/complete
      Mark a bundle item as completed (UI toggle)

FEATURE 5 — MEDICATION ADMINISTRATION TRACKER
═══════════════════════════════════════════════════════════════

Tracks when medications are due, overdue, or administered.
Medication timing errors are the #1 source of preventable 
harm in hospitals. This feature addresses a $17B problem.

Create backend/core/medication_tracker.py:

  Class MedicationTracker:
    Per patient, tracks administration schedule:
    
    MedicationDose(
      dose_id: str,
      patient_id: str,
      medication: Medication,
      scheduled_time: ISO8601,
      administered_time: ISO8601 | null,
      status: "UPCOMING"|"DUE"|"OVERDUE"|"ADMINISTERED"|
              "HELD"|"REFUSED",
      held_reason: str | null,
      nurse_id: str | null,
      alert_sent: bool
    )
    
    Generate schedule for each patient based on 
    their medication frequency:
      QD (once daily): next dose at +24h from "started"
      BID (twice daily): every 12h
      TID: every 8h
      QID: every 6h
      PRN (as needed): no schedule
      
    Status transitions:
      > 30min before scheduled: UPCOMING
      Within 30min: DUE (generate alert)
      Past scheduled time: OVERDUE (generate URGENT alert)
    
    Routes:
      GET /api/medications/{patient_id}/schedule →
        All doses with status, sorted by scheduled_time
      GET /api/medications/overdue →
        All overdue doses across all patients
      POST /api/medications/{dose_id}/administer →
        Mark as administered, timestamp it
      POST /api/medications/{dose_id}/hold →
        Body: {reason: str}
